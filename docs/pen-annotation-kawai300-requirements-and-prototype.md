# ペン書き込み機能：要求の整理と試作（英語長文300・問題1）

本文書は、別会話でユーザーから出された**ペン書き込みに関する要求**と、その後リポジトリに入った**試作実装**の内容を、後から参照できるように Markdown でまとめたものです。原文のチャットログはここには含めず、**試作コード（`annotate-kawai300-p1/`）と UI 上の説明から復元した要求**として記載します。

---

## 1. ユーザー側の要求（整理）

以下は、試作の設計・文言と一致する形に整理した要求です。

1. **教科書ページ画像の上に手書きで書き込めること**  
   参照書ビューア本体に組み込まずともよいが、**教材ページに重ねて書く**体験が欲しい。

2. **座標は画像の論理ピクセル（キャンバス解像度）基準**  
   表示の拡大縮小に依存せず、**画像の naturalWidth / naturalHeight と一致する座標系**にストロークを保存する。これにより縮尺が変わっても線が画像に追従する。

3. **表示の拡大・縮小**  
   細部を書き込みやすいよう、**ビュー倍率（例: 50〜250%）**を変更できること。可能なら設定を端末に記憶する。

4. **ツールのバリエーション**  
   - ペン（フリーハンド）  
   - 蛍光ペン（ハイライト）  
   - 消しゴム（ストロークの一部を消去）  
   - 図形：**直線・矩形・楕円**はドラッグで確定する操作

5. **描画モードの切替**  
   「ペンで書く」オンオフで、**スクロール／ピンチと描画**の競合を避ける（オフ時はキャンバスが pointer-events: none 等）。

6. **データの保存場所**  
   **IndexedDB のみ**（サーバ送信なし）。想定データ量は目安で数 MB 以下。

7. **操作の取り消し・ページ単位の消去**  
   戻す（アンドゥスタック）、そのページの注釈をまとめて消去。

8. **バックアップ・復元**  
   **JSON のエクスポート／ファイルからのインポート**で、端末を替えても復元できるようにする。

9. **試作のスコープ（限定）**  
   まずは **河合塾「やっておきたい英語長文300」の問題1のみ**、**PDF（本誌目安）p.2〜p.3** の2ページに限定して検証する。

10. **実行方法**  
    リポジトリルートで静的サーバ（例: `npx serve`）を立て、`annotate-kawai300-p1/index.html` から利用する想定。

## 2. 試作で実装された内容（現状の仕様）

実装場所: **`annotate-kawai300-p1/`**（`index.html` + `app.js`）。

| 項目 | 内容 |
|------|------|
| 対象ドキュメント | `DOC_KEY = 'kawai300-p1'` |
| 対象ページ | `PAGES`: PDF p.2, p.3（ラベルに本誌目安ページ表記） |
| 画像パス | `../images/kawai_300/page_` + 4桁ゼロ埋め + `.png` |
| IndexedDB | DB 名 `annotate-kawai300-p1`、ストア `pages`、キー `${DOC_KEY}-${pdfPage}` |
| 履歴形式 | ページごとに「レイヤー」の配列の配列（アンドゥはレイヤー単位）。ストロークは `type` 付きオブジェクト（`path` / `line` / `rect` / `ellipse` / `erase`）および従来の `{ points, color, width }` の互換読み込み |
| ビュー拡大 | `#main` に CSS `transform: scale()`、0.5〜2.5、10% ステップ相当。`localStorage` キー `annotate-kawai300-p1-zoom` |
| ツール | `pen` / `highlighter`（multiply + 半透明） / `eraser`（destination-out のパス） / `line` / `rect` / `ellipse` |
| 線幅 | UIの「細・標準・太」に加え、キャンバス幅に応じたスケール（`lineWidthForCanvas`） |
| UI | 「ペンで書く」トグル、ツール・色・太さ、ズーム ±・等倍、戻す・ページ消去、JSON バックアップ・ファイル復元、ステータス表示 |
| PWA 等 | 目次やメインアプリへの組み込みはこの試作範囲外（単体 HTML） |

ファイル先頭のコメント（`app.js`）にも、次の一行要約がある。

> 軽量書き込み試作 — 河合 英語長文300 問題1のみ（PDF p.2–3）  
> ストロークは画像の論理ピクセル座標。拡大・蛍光・消しゴム・図形対応。

## 3. 今後の拡張で検討しうること（試作外）

- メインの `*_viewer.html` / `hs_app.js` との統合（同一オリジン・ルーティング）
- 他書籍・全ページへの一般化（`PAGES` / `IMG_BASE` のデータ駆動化）
- 解答別冊のような **別画像ルート** との切替（`hs_app.js` にある別経路パターンとの整合）
- ストロークデータの圧縮、同期、複数端末間の衝突解消
